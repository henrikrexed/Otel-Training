    Getting started

    Goal: have the tokens you need, a fork of the casino project on the Dynatrace-solution GitLab, and a Codespace starting against that fork. Budget 15 minutes.

    This is the advanced self-paced track

    These pages sit alongside the facilitator-led modules M0–M5, not in place of them. Where M0–M5 walk one planted defect at a time with a helper in the room, this track is a self-paced sequence of seven larger exercises (plus a Step 0 warmup) — instrumentation, business metrics, a semantic-convention guard, cost, cardinality, PII, and sampling. Every step follows one pattern — the Problem → Opencode → Verify loop, where you drive the opencode AI coding agent to produce each fix — and ends with a Dynatrace validation checkpoint you run yourself.

    1. Tokens you need

    Everyone shares one Dynatrace tenant; your work is kept separate by your k8s.cluster.name. Before you create the Codespace, make sure you have the following. The three Dynatrace values are injected as Codespace secrets by the organizers — you usually do not mint them yourself, but you should know what they are and how to check them.

    For the authoritative type/consumer of every Dynatrace variable, see the one canonical table in M0 setup → Environment variables. The subset you need for this track:

    Secret What it is Dynatrace docs
    DT_TENANT Your tenant URL, e.g. https://abc12345.live.dynatrace.com Environment / tenant
    DT_INGEST_TOKEN Platform token (dt0s16) — OTLP ingest, scopes openpipeline:{traces,metrics,logs,events}:ingest + storage:metrics:write Platform tokens
    DT_OPERATOR_TOKEN Platform token (dt0s16) for Kubernetes monitoring (ActiveGate / operator) — fleet-management:* + settings:objects:*. Renamed from DT_API_TOKEN, still accepted as a deprecated fallback. Platform tokens
    DT_PLATFORM_TOKEN (optional) Platform token (dt0s16) used only by dtctl — same token type as the two above but a distinct scope set Platform tokens
    GITLAB_REPO_URL HTTPS URL of your casino fork (see step 2) —
    GITLAB_TOKEN Token scoped to your fork (read_repository + write_repository) GitLab access tokens
    WORKSHOP_DISPENSER_URL Endpoint that mints your per-attendee LLM proxy key (for opencode in Step 1) — not a Dynatrace token —
    WORKSHOP_ROOM_PASSWORD Shared room password sent to the dispenser — not a Dynatrace token —

    The two WORKSHOP_* secrets are only for Step 1

    They wire the opencode AI coding agent to a facilitator-hosted LLM proxy. If they are not set, the Codespace still comes up fully — only the Step 1 AI-agent instrumentation flow is unavailable (post-create setup says so and moves on). Your per-attendee budget is enforced on the proxy; there is nothing to configure for it locally.

    Davis CoPilot (optional) — a separate OAuth client

    If your cohort runs the optional Davis CoPilot exercise, it uses a Dynatrace OAuth client (dt0s02), not any of the tokens above. It is kept deliberately separate from the required DT token set and is only wired when that exercise is in scope. Nothing on the main M0–M5 path or in this track's required steps needs it, so skip it unless a facilitator says otherwise.

    You never paste a token into the repo

    Tokens live only as Codespace secrets and are read at runtime. Nothing is written to disk or committed. If you ever find yourself pasting a token into a file, stop — that is not the flow.

    2. Fork the casino project (do this before the Codespace)

    This track uses GitLab + Argo CD, because GitLab is part of the Dynatrace solution. You fork the upstream casino project into the shared GitLab, and your Codespace's Argo CD syncs from your fork.

    Placeholders below: <gitlab-host> is the Dynatrace-solution GitLab from your welcome email; <attendee> is your GitLab username.

    1. Sign in to the shared GitLab at https://<gitlab-host>/ with the account from your welcome email.
    2. Open the upstream project https://<gitlab-host>/otel-training/casino.
    3. Click Fork and select your namespace. You now own https://<gitlab-host>/<attendee>/casino, containing the Kubernetes manifests under k8s/.

    Create a token scoped to your fork

    1. In your fork → Settings → Access Tokens (a Project Access Token), or your user Preferences → Access Tokens (a Personal Access Token).
    2. Scopes: read_repository (Argo CD pulls from the fork) and write_repository (so you can push your edits back).
    3. Copy the token value now — GitLab will not show it again.

    3. Inject the fork URL and token as Codespace secrets

    In GitHub → Settings → Codespaces → Repository secrets (or at Codespace creation time), set:

    Secret Value
    GITLAB_REPO_URL https://<gitlab-host>/<attendee>/casino.git
    GITLAB_TOKEN the token from step 2
    GITLAB_USERNAME (optional) your username; defaults to oauth2, which is valid for GitLab tokens over HTTPS

    4. Start the Codespace

    1. Open the training repository you received in your welcome email.
    2. Code → Codespaces → Create codespace on main.
    3. Post-create setup runs automatically. Seeing GITOPS_PROVIDER=gitlab plus your two GitLab secrets, it installs Argo CD and points the casino Application at your fork. Typically 3–5 minutes with a prebuild.

    Offline / air-gapped fallback

    If the GitLab secrets are not present, the bootstrap falls back to an in-cluster Gitea host (GITOPS_PROVIDER=gitea) and prints how to switch. The Argo CD lab loop is identical either way — only the Git host differs.

    Dynatrace validation checkpoint

    You have not instrumented anything yet, so this checkpoint just proves the plumbing:

    1. echo $DT_TENANT, open the URL, and sign in with the credentials from your handout.
    2. Go to Infrastructure → Kubernetes and confirm a cluster named after your PARTICIPANT_ID appears (first appearance can take a few minutes).
    3. Set a filter k8s.cluster.name = your PARTICIPANT_ID and save the view. You will reuse it on every step.

    Definition of done

    • You can name the secrets in the table above and what each is for
    • You own a fork https://<gitlab-host>/<attendee>/casino
    • GITLAB_REPO_URL and GITLAB_TOKEN are set as Codespace secrets
    • The Codespace is created on main and post-create setup finished
    • Your cluster appears under Infrastructure → Kubernetes in Dynatrace
