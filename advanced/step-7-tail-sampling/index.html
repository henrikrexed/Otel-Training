    Step 7 — Tail sampling

    The labs/advanced/ directories keep their original feature-ordinal numbering, so they run one behind these doc steps — this page's assets live under labs/advanced/step6-tail-sampling/.

    Goal: cut trace ingest cost sharply while keeping every trace that matters — errors, slow traces, and jackpots. Budget 25 minutes.

    The concept

    Sampling is a strategy, not a failure — 100% is rarely the answer, but blind head sampling (deciding SDK-side, before the trace exists) throws away the errors you most need. Tail sampling buffers the whole trace, then keeps all errors / slow traces / jackpots and samples the boring majority down to 10%.

    flowchart LR spans["all traces
    (buffered 10s)"] --> ts{"tail_sampling
    decision"} ts -->|"status = ERROR"| keep1["keep 100%"] ts -->|"latency > 1s"| keep2["keep 100%"] ts -->|"casino.outcome = jackpot"| keep3["keep 100%"] ts -->|"everything else"| samp["keep 10%"] keep1 --> dt[("Dynatrace")] keep2 --> dt keep3 --> dt samp --> dt

    Before — export everything

    No sampling at the gateway — every trace is exported. Trace ingest cost scales linearly with casino load, and most of it is fast, successful, uninteresting spins.

    ② Opencode — tail sampling at the gateway

    Drive opencode at the gateway with the otel-collector skill — goal (the four policies), target file, skill:

    opencode run "Using the otel-collector skill: in observability/collectors/gateway.yaml \
add a tail_sampling processor to the TRACES pipeline with decision_wait 10s and \
four policies — status_code=ERROR keep 100%, latency>1s keep 100%, \
casino.outcome=jackpot keep 100%, and everything else probabilistic at 10%. Place \
it after k8sattributes/resource and before batch; keep memory_limiter first."

    ③ Review — read the diff

    Confirm all four policies are present, decision_wait is 10s, and the processor is in the traces pipeline after k8sattributes/resource, before batch. Reference answer: labs/advanced/step6-tail-sampling/tail-sampling-processor.yaml.

    If the agent gets it wrong — steer it back

    If it drops the jackpot policy or samples errors, reply "errors, slow (>1s), and jackpots must each keep 100% — only the remaining 'boring' traces sample to 10%."

    ④ Apply — kubectl

    kubectl apply -f observability/collectors/gateway.yaml

    Policies: status_code=ERROR → 100%, latency > 1s → 100%, casino.outcome=jackpot → 100%, everything else → 10% probabilistic. The decision_wait buffer is 10s — long enough to assemble a full trace before deciding.

    Single-instance requirement

    Tail sampling must see all spans of a trace on one collector instance. The training gateway is replicas: 1, so this holds. If you scale the gateway out, you must front it with a loadbalancing exporter tier keyed on traceID — otherwise decisions are made on partial traces and you drop spans from traces you meant to keep.

    Dynatrace validation checkpoint

    Confirm errors are retained while overall volume drops, in a Grail Notebook:

    fetch spans, from: now() - 1h
| summarize kept = count() by { status = if(request.status == "failed", "error", "ok") }
    • Before: error traces are a small % of total, matching their natural rate; total volume is high.
    • After: total trace volume drops sharply, but the absolute count of error / slow / jackpot traces is unchanged (100% retention) — error analysis stays complete while cost falls. Verify a known error trace is still fully present end-to-end.

    Definition of done

    • The tail_sampling processor is wired into the traces pipeline (after k8sattributes/resource, before batch)
    • The four policies are in place (error / slow / jackpot → 100%, else 10%)
    • Total trace volume drops after the fix
    • The absolute error/slow/jackpot count is unchanged
    • A known error trace is still complete end-to-end
